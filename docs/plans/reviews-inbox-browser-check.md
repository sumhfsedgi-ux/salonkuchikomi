# 届いた口コミ 第1段階:ブラウザでの通しの確認(架空の Google)

対象:`feature/reviews-inbox`(口コミの実装計画 第2版の第1段階)。
目的:テスト用の環境で、架空の Google・架空の返信案を使い、画面の流れと状態を PC とスマートフォンの幅で確かめる。

この確認に含めないもの(公開の前に別に確認する):
- Google の規定との関係(25日の一時保存、絞り込み、新着の記録)
- プライバシーポリシーと同意文の最終の文言
- 期限切れの削除の定期実行(外部のスケジューラー)
- 実在の店舗での読み取り、実際の返信

実際の Google への投稿、OpenAI・LINE への呼び出しは行わない。

## 1. 前提(テスト用の環境が決まってから)

環境は、どちらかに決めてから準備する。どちらも、作業の前に対象を示して確認を取る。

- **A. 共有テストDBを使う**
  1. 古い口コミの表と関数(旧 0015〜0017)を片付ける。対象と戻し方は、別に示した一覧のとおり。
  2. `npm run testdb:migrate -- --apply` で 0027〜0030 を適用する。`--reapply-changed` は使わない。0026 は適用済みのため、変えない。
- **B. 口コミ専用のテスト用プロジェクトを使う**
  - プロジェクトはご本人が作る。
  - このフォルダの `.env.testdb.local` をそのプロジェクトに向け、`npm run testdb:migrate -- --apply` で 0001〜0030 を適用する。

どちらでも、確認のために次の値を入れる。行を足す・変えるのは、作業の前に一覧を示してから。

- `feature_catalog` の `google_reviews` を `available` にする。テスト用の環境だけで、本番は変えない。
- 確認用の店舗にだけ、`salon_feature_overrides` で `google_reviews = allow` を入れる。
- 確認用の店舗とログインを作る。
  - 口コミプランで許可ありの店舗(アンケートなし)
  - SalonPack プランで許可ありの店舗
  - 口コミプランで許可なしの店舗(比較用)

## 2. 起動と、架空の Google の操作

```
npm run dev:testdb:reviews        # http://localhost:3200
```

起動の仕組み:
- `.env.testdb.local` の接続先を確かめてから起動する。
- `GOOGLE_REVIEWS_OAUTH_ENABLED=1` で起動する。
- OpenAI の値は空にする。このフォルダの `.env*` に `OPENAI_API_KEY` があれば起動しない。

架空の Google には、次のアカウントと店舗がある。

| アカウント | 店舗 | 口コミ | 使う場面 |
|---|---|---|---|
| owner@example.test | 渋谷店(sim-101) | 4件。返信なし・公開できなかった返信・公開済みの返信・写真つきを含む | 一覧と状態の表示 |
| owner@example.test | 新宿店(sim-102) | 2件 | 店舗の変更 |
| owner@example.test | 準備中の店(sim-103) | — | オーナー確認が済んでいない(選べない理由の表示) |
| owner@example.test | 口コミ0件の店(sim-201) | 0件 | 口コミ0件の表示 |
| owner@example.test | 口コミが多い店(sim-202) | 120件 | 取得の途中と続き。連絡先を含む本文や、返信案の作成が失敗する口コミ(「生成失敗」)もある |
| staff@example.test | (ビジネスなし) | — | 管理しているビジネスが見つからない |

失敗・遅れ・応答の消失は、開発サーバーの `POST /api/dev/simulated-gbp` で次の1回に仕込む。この口は架空モードでだけ使える(本番ビルドでは 404)。ブラウザの開発ツールから、例えば次のように送る。

```js
await fetch("/api/dev/simulated-gbp", { method: "POST", headers: { "content-type": "application/json" },
  body: JSON.stringify({ action: "fail_next", operation: "reviews", kind: "unavailable" }) });
```

| action | 内容 |
|---|---|
| `fail_next` {operation, kind} | 次の1回を失敗させる。operation:accounts / locations / reviews / review / reply / delete_reply。kind:timeout / unavailable / permission_denied / scope_insufficient / service_disabled / failed_precondition / rate_limited / not_found など |
| `delay_next` {operation, ms} | 次の1回を遅らせる(60秒まで) |
| `lose_next_response` {operation} | reply・delete_reply を反映したうえで、応答を返さない(時間切れ) |
| `delay_next_ai` {ms} | 次の返信案の作成を遅らせる |
| `set_reply_state` {reviewName, state, policyViolation?} | 返信の審査の状態を変える(PENDING / APPROVED / REJECTED) |
| `set_reply_externally` {reviewName, comment\|null} | SalonPack の外で返信を書き換える・消す |
| `add_review` / `edit_review` / `remove_review` | 口コミを足す・投稿者が編集する・Google 上で消す |
| `set_average` {locationName, averageRating, totalReviewCount} | Google の口コミ数・平均を変える |
| `expire_page_tokens` | 続きのページの指定を受け付けなくする |
| `fail_next_token_refresh` {kind} | 次のトークンの更新を失敗させる(invalid_grant) |
| `reset` | 架空の Google を最初の状態に戻す |

`GET /api/dev/simulated-gbp` は、架空の Google への呼び出しの記録(最後の50件)を返す。同意の前に呼び出しが無いことの確認に使う。

## 3. 確かめる項目

PC(1280px)とスマートフォン(390px)の両方で行う。スマートフォンの幅では、ページが横にはみ出さないことも見る。

### 3-1. 未連携から、同意・店舗の選択・取り込みまで
- [ ] 届いた口コミのタブに説明と同意のチェックがあり、チェックしないと連携を始められない。
- [ ] 予約メールと同じアカウントがある店舗では、「予約メールと同じアカウントで連携する」が出る。
- [ ] 連携のあと、店舗の一覧が出る。準備中の店は理由つきで選べない。
- [ ] 選ぶと最初の取り込みが走り、一覧が出る。既定の絞り込みは「未返信」。
- [ ] **共通の Google 連携の画面から口コミを連携した場合**:
  - 届いた口コミのタブで、先に「口コミの取り扱いについて確認してください」が出る。
  - 確認するまで、`GET /api/dev/simulated-gbp` の記録に accounts・locations・reviews が無い。
  - 確認すると、店舗の選択に進む。
- [ ] staff@example.test で連携すると、「管理しているビジネスが見つかりません」と、その理由の候補が出る。

### 3-2. 口コミ0件・取得の途中・失敗・再連携
- [ ] 口コミ0件の店:
  - 「まだGoogle口コミはありません」が出る。
  - 口コミ数は「0件」(Google が 0 と返したため)、平均は「—」。
- [ ] 取得の途中:
  - 口コミが多い店を選ぶ前に `delay_next` {reviews, 11000} を仕込む。
  - 初回の取り込みが途中で区切られ、「取得しています」または「続きを取得する」が出る。
  - 続きで全件になる。
  - 初回の分は新着に数えない。
- [ ] 失敗:
  - `fail_next` reviews unavailable のあと［更新］を押すと、「時間をおいて…」と出て、一覧は残る。
  - permission_denied では「この店舗を管理する権限…」と出る。
  - scope_insufficient では権限不足の画面になる。予約メール(Gmail)の連携は変わらない。
- [ ] 再連携:
  - 確認用の店舗の Google アカウントを「再連携が必要」にする。これはテスト用の DB の行を1つ変える作業なので、作業の前に示す。
  - 「Googleとの連携の確認が必要です」と［Googleに再接続する］が出る。
  - 再接続すると元に戻る。

### 3-3. 未返信・返信済み・結果不明
- [ ] 投稿の流れ:
  - 未返信の口コミに返信を書き、［Googleに返信する］を押すと確認のダイアログが出る。店舗名・口コミ・投稿する全文が見える。
  - 送ると「送信結果を確認中」になる。
  - ［Googleで確認する］で「審査中」になる。
  - `set_reply_state` APPROVED で「公開済み」になる。REJECTED と policyViolation で「公開できませんでした」と理由が出る。
- [ ] 結果不明(反映されていない場合):
  - `fail_next` reply timeout のあと送ると、「送信結果を確認中」になる。操作は［Googleで確認する］だけ。
  - 2分以内に確認すると、「まだ反映を確かめられませんでした」が出る。
  - 2分を過ぎて確認すると、「送信できませんでした」になる。そこで初めて［もう一度送る］と［送るのをやめる］が出る。
  - ［送るのをやめる］のあとは、ふつうの「未返信」になる。Google には何も送らない。
- [ ] 結果不明(反映されていた場合):
  - `lose_next_response` reply のあと送ると、「送信結果を確認中」になる。
  - 確認すると「審査中」になる(反映されていた)。
- [ ] 置き換えと削除の失敗:
  - 返信済みの口コミで置き換えに失敗すると(`fail_next` reply permission_denied)、「置き換えできませんでした」になり、残っている返信と編集中の文章が並ぶ。
  - 削除の失敗では「削除できませんでした」になる。
- [ ] 競合:
  - 確認のダイアログを開いたまま `set_reply_externally` で外から返信を変えて送ると、送らずに競合の表示になる。
- [ ] 一覧の行の状態と絞り込み(未返信・確認が必要・返信済み・すべて・新着)が、詳細の状態と合う。

### 3-4. AI の返信案・編集・再生成・投稿の確認
- [ ] ［AIで返信案を作る］で、架空の返信案(「【検証用の架空の返信案】」で始まる)が返信欄に入る。
- [ ] 文章を手で直してから［AIで別の案を作る］を押すと、直した文章は残り、案は「別の案」として出る。
- [ ] 直していなければ、案は入れ替わる。
- [ ] 作っている間に入力しても、その入力は上書きされない。
- [ ] 「生成失敗」の口コミでは失敗の案内が出て、返信欄の文章は残る。
- [ ] 下書きの保存の表示が出る。移動するときの確認(保存していない・送信中)が出る。

### 3-5. 連携の解除・店舗の変更と、実行中の処理が重なる場合
- [ ] 返信案の作成中:
  - `delay_next_ai` 8000 のあと案を頼み、その間に別のタブの設定で店舗を変える。
  - 案は表示されず、「連携が変わったため…」が出る。
- [ ] 送る直前:
  - `delay_next` review 5000 のあと送り、その間に店舗を変える。
  - 送らずに「返信は送っていません」と出る。架空の Google に返信が付かない。
- [ ] 送り始めたあと:
  - `delay_next` reply 5000 のあと送り、送信中に店舗を選び直す(同じ店)。
  - 結果は記録だけ残る。新しい一覧では「送信結果を確認中」で、確認すると反映が分かる。
- [ ] 取り込み中:
  - `delay_next` reviews 5000 のあと［更新］を押し、その間に「口コミの連携をやめる」を押す。
  - 取り込んだ内容は書き戻されない。予約メールの連携は変わらない。

### 3-6. 口コミプランのログイン後の入口
- [ ] 口コミプランで許可ありの店舗:
  - ログインすると「届いた口コミ」に入る。アンケートが無くても、初期設定に飛ばされない。
  - タブは3つ(口コミを集める・届いた口コミ・設定)。
- [ ] 「口コミを集める」タブでは、アンケートが無ければ作成の案内が出る。
- [ ] 許可なしの店舗では、今までと同じ入口になる。タブは出ず、届いた口コミの URL は 404。
- [ ] SalonPack プランの店舗では、ホームは今まで通り。「口コミ」から3つのタブが使える。

### 3-7. PC とスマートフォンの表示
- [ ] PC:
  - 一覧(左)と詳細(右)の2列。
  - 新着の帯、口コミ数・平均のカード、最終更新と［更新］が1行に並ぶ。
- [ ] スマートフォン:
  - 詳細は全画面で、「‹ 一覧へ」で戻れる。
  - 絞り込みとタブは横にスクロールできる。
  - 返信の操作は返信欄のすぐ下にあり、下のメニューと重ならない。
  - ダイアログが画面に収まる。

## 4. 結果の残し方
- 各項目の結果(PASS / FAIL と画面の状態)と、PC・スマートフォンの画面の画像を残す。画像は作業用のフォルダに置き、リポジトリには入れない。
- 実際の Google・OpenAI・LINE への通信が無いことを、ブラウザの通信の記録で確かめる。
