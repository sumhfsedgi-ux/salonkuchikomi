# 口コミ返信生成 reply-v1.4 の変更と検証

2026-10-16。`feature/reviews-inbox` の返信生成の修正記録。検証後にユーザーから同ブランチへのコミット・push の指示を受け、この記録も変更と一緒に含める。デプロイ・DB の変更・Google 投稿・LINE/メール送信はしていない。第2段階の実装ではない。

## 変更した理由と内容

- v1.3 は補償関連の単語だけでも文を削っており、返金の要望や肌の異常に触れない一般的なお礼になる場合があった。要望への言及と補償の約束を分け、問題があれば重要な内容を保持して1回だけ修正する。修正後も内容の問題が残れば案を返さない。文の自動削除は廃止。
- 口コミにない人数・笑顔・記憶を作らないよう指示し、語彙ベースの検査を追加。AI が返す引用も原文と照合する。これらは事実性を全面的に保証する検査ではない。
- 料金、待ち時間、説明、返金、肌の状態、治療費などの主な話題が、混合・慎重モードの返信から抜けていないか補助検査する。
- ★3という理由だけで不満があると扱わない。本文なしは★1でも評価へのお礼とし、書かれていない体験を補わない。低評価の再来店抑止と設定済みの連絡先の付加は維持。
- 日本語と明確な英語の入力を区別。英語の入力には英語の本文を作り、主要な英語の禁止表現も検査する。署名・連絡先は店舗の設定どおり付け、翻訳しない。
- 口調・長さ・再生成時の構成の違いを指示。長さは店舗で選んだ設定に従う。利用者が削除を希望した「短い口コミには、不要な店舗紹介や一般論で文章を膨らませない」という条件は追加していない。
- 長さの目安を外れた案は1回修正する。なお外れる場合は本文を切らず、既存の注意表示に「選択した長さの目安から外れています」を返す。Google のバイト上限は署名等の付加後にも検査し、超える案は返さない。

UI の構造、認可・同意、投稿前の確認、投稿競合、予約通知、DB migration、Preview 停止設定は変更していない。画面確認用の架空の返信生成も新しい検査を通るよう調整した。

## 実際の AI で確認した範囲

以前の架空の口コミ21件を同じ `gpt-4o-mini` で再生成した。実在の口コミや顧客情報は送っていない。電話番号・URLを含む架空入力も従来の伏せ字処理を通した。APIキーをファイルやレポートへ書き出していない。

全21件と作り直し1件の生成を確認したあと、文面を目視し、待ち時間の不自然な敬語と「時間を無駄にしてしまった」という未確認の断定を追加修正した。長さの指定も具体化し、関連5件を再生成した。全件比較と5件の追加比較は別々に保存している。生成成功を「文章品質の満点」とは扱わない。

改善を確認した例:

- 「友人と楽しかった」への返信に、以前あった「お二人の笑顔」の創作は今回の出力ではない。
- 英語の口コミへの本文は英語になった。
- 返金の要望、肌の赤み・ヒリヒリ感、治療費の要望が残り、返金や支払いの約束にはなっていない。
- 同じ口コミの追加比較では「短め」は74文字、「丁寧に詳しく」は本文152文字＋署名。違いは出たが、後者は160〜300文字の目安には届かず、注意付きで返った。

## 残る制約

- 長さの指定は厳密ではない。追加比較でも詳しく設定の2件は目安未満だった。再生成によって変動する。
- 「嬉しく思います」「しっかり受け止める」等の定型句や、店舗側の仕事を自己評価する言い回しはまだ残る。文体の多様性・自然さが完全に解決したとは言わない。
- 分類・検査は語彙による補助で、否定、言い換え、未知の話題、複雑な事実関係を網羅しない。日本語・明確な英語以外は日本語にフォールバックする。投稿前の人による確認が必要。
- 旧出力は保存済みの例であり、旧生成時の乱数等をそろえた統計的な比較ではない。今回、別のAIモデルによる採点は実行していない。
- 新しい検査により修正呼び出しが増える場合がある。既存の時間予算を維持し、生成＋修正の最大2回に制限する。

## 再現方法

架空入力と旧返信は `scripts/eval/fixtures/reply-quality-baseline.json`。通常の単体テストから外部AIは呼ばない。

明示的な評価のみ、環境に `EVAL_RUN=1` と `OPENAI_API_KEY` を設定して次を実行する。秘密値はコマンドやチャットに直接記載しない。

```text
node node_modules/vitest/vitest.mjs run --config vitest.eval.config.mts scripts/eval/reply-quality.eval.ts
```

出力は `.eval-output/reply-quality-reply-v1.4/comparison.json` と `comparison.md`。`EVAL_SAMPLE_INDEXES=7,9,13,19,20` なら指定ケースのみを実行し、`focused-comparison` に保存する。実際の応答の詳細はこの架空データ専用の評価にだけ保存し、サービスのログには加えていない。
