# 認証メールのテンプレート(Supabase の管理画面: Authentication → Email Templates)

0025 の手順書(`salon-onboarding-runbook.md`)の段5で設定する。**新しいアプリのデプロイのあとに変える**(旧アプリには `/auth/confirm` が無い)。

**決めたこと**
- テンプレート1つにつき、用途は1つにする。ユーザーの metadata を使って文面を切り替える方式は使わない。
  - 同時に送ったときや、前の値が残ったときに、文面が入れ替わるおそれがあるため。
  - `.Data`(本人が書き換えられる metadata)は、文面に入れない。
- サロン名などの店舗の情報は、文面に入れない(テンプレートで信頼できる値を使えないため)。
- リンクは自分たちの `/auth/confirm` に向け、トークンはフラグメント(`#`)で渡す。
  - フラグメントはサーバーに送られないため、アクセスログに残らない。
  - 画面ではボタンを押してから検証する。メールの先読みでトークンが使われてしまうのを防ぐため。
- リンクの土台は `{{ .SiteURL }}` にする。Site URL を本番の URL にしておく。管理画面から送る招待には戻り先が無いため、`{{ .RedirectTo }}` は使わない。
- `type` の値は、testdb で確かめたもの。
  - 新規登録の確認: `email`
  - 招待: `invite`
  - Magic Link: `magiclink`

| テンプレート | 用途(アプリの呼び出し) | 変えるか |
|---|---|---|
| Confirm signup | 新規登録の確認と再送(`signUp`・`resend`) | 変える |
| Invite user | 新しいアカウント・未確認のアカウントへの招待(`inviteUserByEmail`)。管理画面から送る招待にも使われる | 変える |
| Magic Link | 本人確認が済んだ既存のアカウントへの、店舗登録のお知らせ(`signInWithOtp`)。**この用途だけ** | 変える |
| Reset password | 既存のパスワード再設定と、本人確認のリンク(本人確認がまだのアカウント) | **変えない**(既存の再設定の画面が今の形のリンクで動いているため) |

## メールの目的と、届いたあとの画面(5種類。2026-10-15)
画面の説明とメールの目的を、次の表にそろえる。どのメールも、受付は「送った・届いた」という意味ではない(画面もそう書かない)。

| メール(テンプレート) | 目的 | 届く場面 | リンクの先と、画面の説明 |
|---|---|---|---|
| 確認メール(Confirm signup) | メールアドレスの確認 | お客様が自分で新規登録したとき・確認メールの再送(新規登録の画面・ログイン画面) | `/auth/confirm`(「下のボタンを押すと、メールアドレスの確認を完了して、次の手続きに進みます」)→ 登録したパスワードを入力 → 店舗の情報 → 利用開始待ち |
| 招待(Invite user) | 運営が登録した店舗の担当者のアカウントの用意と、パスワードの設定 | 運営の本登録(新しい・未確認のアカウント)と、その再送 | `/auth/confirm`(「招待を受けて、パスワードの設定に進みます」)→ パスワードを設定 → 利用開始待ち |
| 店舗登録のお知らせ(Magic Link) | 本人確認が済んだ既存のアカウントに、店舗が登録されたことを知らせる | 運営の本登録(本人確認済みのアカウント)と、その再送 | `/auth/confirm`(「ログインして、登録内容の確認に進みます」)→ 利用開始待ち(パスワードは変わらない) |
| 本人確認(Reset password) | パスワードの設定・入力による本人確認 | 運営の再送(確認済みで本人確認がまだのアカウント)・本人確認の画面の「本人確認のメールを送る」 | `/auth/confirm` → パスワードを入力または設定。**パスワード再設定と同じテンプレートで届く**ため、画面(本人確認の画面・運営の招待と案内)で「パスワード再設定と同じ形式のメールで届きます」と伝える |
| パスワード再設定(Reset password) | 既存のパスワード再設定 | ログイン画面の「パスワードをお忘れですか？」 | `/reset-password`(既存の画面のまま。変えない) |

- 本人確認とパスワード再設定は、同じテンプレートを使う(Supabase のテンプレートは用途ごとに1つで、本人確認に使える別のテンプレートが無い)。
  - 両方の目的で読める文面の案を下の「Reset password(本人確認と共用・案)」に書いた。**未適用**。本番への設定は、手順書の段5で、ほかのテンプレートと一緒に行う。
  - `{{ .ConfirmationURL }}` は変えないので、今のパスワード再設定の流れは壊れない。

## 差出人と問い合わせ先(2026-10-15 の状態)
| 項目 | 状態 | 備考 |
|---|---|---|
| 送信元アドレス | 未決定 | 独自の SMTP(手順書の段1)で決める。標準の SMTP のままでは、プロジェクトのメンバー以外に届かない。本番・テスト用の今の設定は確かめていない |
| 差出人名 | 未決定 | 同上(独自の SMTP の設定で決める) |
| 問い合わせ先(画面) | `NEXT_PUBLIC_SUPPORT_CONTACT_URL`・`NEXT_PUBLIC_SUPPORT_CONTACT_LABEL` | 本番の値は確かめていない。未設定なら、画面に問い合わせ先は出ない |
| 問い合わせ先(メールの文面) | 無い | 店舗登録のお知らせの「運営までお問い合わせください」には、連絡先が書かれていない。決めたら文面に足す |

## Reset password(リンクは変えない。文面は本人確認と共用・案。未適用)
- 既存のパスワード再設定は、今のテンプレート(`{{ .ConfirmationURL }}`)のまま動く。

- 文面の案(どちらの目的でも読める文。リンクは今のまま):

## そのほかの設定
- **メールのリンクの有効期限**(Email OTP Expiration): プロジェクト全体の設定で、すべてのリンクに効く(パスワード再設定も同じ)。招待だけを長くすることはできない。
- **独自の SMTP**: 必須。標準の SMTP は、プロジェクトのメンバー宛てにしか届かず、1時間に2通まで。
- **メールのリンクの書き換え**: SMTP の業者がリンクを計測用に書き換える機能は、オフにする。Supabase の資料が、リンクが壊れる原因として挙げている。
- **確かめていないこと**(開発の作業で確かめられなかった):
  - テンプレートの見た目
  - 実際の送信と到達
  - メールの先読みへの実際の効果
